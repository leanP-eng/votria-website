## BLOC 2 — Positionnement et principes

### 2.1 Positionnement central

> **VotrIA aide les PME du bâtiment à traiter leurs devis, leurs emails et leurs informations chantier sans remplacer leurs outils existants.**

### 2.2 Cible

- PME du bâtiment de **10 à 25 salariés**
- Second œuvre prioritaire : électricité, plomberie/CVC, menuiserie
- Zone prioritaire : Occitanie, avec démarrage Gers et Haute-Garonne
- Extension 26 à 50 salariés uniquement lorsque l'opportunité reste compatible avec le socle VotrIA

### 2.3 Accroche de référence pour le site

> **Vos demandes de devis restent suivies. Vos factures en retard ressortent. Vos comptes rendus arrivent au bureau.**

Sous-titre :

> Pour les entreprises du second œuvre de 10 à 25 salariés. Sans remplacer votre logiciel. Le système prépare et classe, votre équipe garde la décision.

### 2.4 Principes non négociables

1. Le client conserve son ERP et ses outils métier.
2. Aucune écriture automatique dans l'ERP au lancement.
3. Les règles métier sont configurables et réutilisables ; elles ne sont pas recodées intégralement pour chaque client.
4. La validation humaine reste obligatoire avant tout envoi commercial ou toute diffusion client.
5. Les cas ambigus sont placés dans une file d'exceptions.
6. Les développements spécifiques non réutilisables sont refusés ou facturés séparément.
7. Le client reste responsable de l'exactitude et de la fraîcheur de ses données.
8. Les comptes, abonnements et environnements techniques sont détenus par le client.
9. VotrIA ne centralise pas les données de production de ses clients sur une plateforme mutualisée lui appartenant.
10. Les fournisseurs tiers, leur rôle et leurs coûts sont communiqués avant engagement.
11. VotrIA ne reconstruit pas une fonction que l'ERP du client couvre déjà correctement.
12. Une automatisation n'est proposée que si le processus se répète, dispose d'une source exploitable et possède un responsable interne.

### 2.5 Formulation validée sur l'hébergement

> **Votre environnement, vos abonnements, vos données. VotrIA installe et maintient le fonctionnement selon la formule choisie.**

Précision publique :

> La solution est installée dans un environnement dédié à votre entreprise. Les comptes techniques restent à votre nom. VotrIA ne centralise pas les données de ses clients sur une plateforme mutualisée lui appartenant.

### 2.6 Domaines de solution

1. **CAP CASH** : traiter les demandes, suivre les devis, prioriser les relances et les encaissements.
2. **CAP CHANTIER** : structurer les informations terrain, les comptes rendus, les documents et les travaux supplémentaires.
3. **CAP SUIVI CHANTIER — Y2** : suivre les décisions, responsables, échéances et réserves jusqu'à leur clôture.

- parler plutôt qu'écrire ;
- aucune nouvelle application ;

- questions courtes uniquement en cas d'ambiguïté.

Risque : une solution parfaite au bureau qui n'est jamais alimentée.

Message :

Attentes :

- comptes appartenant au client ;
- accès nominatifs ;
- périmètre documenté ;
- sauvegarde et responsabilités explicites ;
- aucun serveur sauvage ni contournement de sécurité.

Message :

> L'environnement appartient au client. Les accès, fournisseurs et responsabilités sont documentés avant la mise en production.

### 3.3 Règle d'adoption

Une solution n'est considérée comme vendable que si :

- le dirigeant comprend le résultat ;
- le bureau gagne réellement du temps ;
- le terrain conserve un geste naturel ;
- l'infrastructure peut être administrée sans dépendance permanente et informelle.

## BLOC 4 — Architecture commerciale

### 4.1 Concept général

VotrIA commercialise deux offres principales progressives : **CAP CASH** et **CAP CHANTIER**.

Chaque offre commence par une petite brique utile, standardisée et tarifée. Les extensions réutilisent uniquement les composants réellement communs : source, accès, environnement, utilisateurs, pivot, stockage ou interface de validation.

> **Commencez par une tâche précise. Gardez ce qui fonctionne. Étendez seulement lorsque votre équipe l'utilise.**

### 4.2 Deux parcours d'entrée

#### Parcours A — besoin standard

Qualification gratuite de 15 à 20 minutes lorsque le besoin correspond exactement à une fiche :

- une entreprise ;
- une source ;
- un processus ;
- outils déjà maîtrisés par VotrIA ;
- aucune reprise historique ;
- aucune règle spécifique.

Parcours :

```text
Qualification courte → offre à prix fixe → installation → mesure de mise en service → extension éventuelle
```

#### Parcours B — besoin complexe

Diagnostic à **490 € HT** lorsque plusieurs outils, équipes, sociétés ou processus sont concernés.

Le diagnostic couvre :

- douleur prioritaire ;
- fonctionnement actuel ;
- personne référente ;
- première vérification du logiciel et des données ;
- solution recommandée ;
- ordre de grandeur du budget ;
- décision : automatiser, attendre ou ne pas automatiser.

Aucun fichier n'est exigé pour réserver. Après réservation, VotrIA contacte la personne qui utilise réellement le logiciel. Si aucun export n'est disponible, une tentative d'extraction peut être réalisée en partage d'écran. L'absence de fichier ne bloque pas le diagnostic, mais une proposition ferme exige une méthode de récupération reproductible.

## BLOC 8 — Maintenance, services tiers et responsabilités

### 8.1 Surveillance technique — 99 € HT/mois

### 8.2 Maintien opérationnel — 149 € HT/mois

Comprend en plus :

- jusqu'à 30 minutes d'intervention par mois ;
- temps non reportable ;
- prise en compte sous un jour ouvré.

Au-delà : intervention facturée après accord.

### 8.3 Application du MCO

- flux ponctuel ou local : abonnement facultatif ;
- email automatisé, WhatsApp ou connexion automatisée : surveillance technique minimale obligatoire ;
- réunion chantier déposée ponctuellement : aucun abonnement VotrIA obligatoire ;
- aucune garantie de rétablissement sous 24 h ;
- une prise en compte ne vaut pas garantie de résolution ;
- changement du fait du client ou d'un fournisseur tiers facturé séparément.

### 8.3 bis — Facturation par environnement (décision VotrIA)

> La surveillance ou le maintien opérationnel est facturé par environnement client et couvre jusqu'à trois flux standard actifs. Au-delà, le périmètre et le tarif sont adaptés avant engagement.

Cette règle précise l'application du MCO (BLOC 8.3) : l'abonnement n'est pas dû une fois par brique installée, mais une fois par environnement client, tant que le nombre de flux standard actifs reste inférieur ou égal à trois. Elle s'applique notamment lorsque plusieurs briques à canal automatisé (Demandes de devis, Suivi et relance des devis, Factures et encaissements, WhatsApp → compte rendu chantier, Revue des emails prioritaires) sont installées dans le même environnement.

## BLOC 13 — Garde-fous de rentabilité et risques

### 13.1 Temps maximum par offre standard

| Offre | Temps VotrIA maximal |
|---|---:|
| Demandes de devis à traiter | 7 h |
| Revue des emails prioritaires | 7 h |
| Réunion chantier → compte rendu | 5 h |
| WhatsApp → compte rendu chantier | 10 h |

Le temps comprend : installation, configuration, tests, échanges client, documentation, formation et corrections de mise en service.

Dépassement récurrent = réduction du périmètre ou hausse du prix. Jamais du travail gratuit permanent.

### 13.2 Risques prioritaires

1. **Acquisition insuffisante** : trop peu de conversations qualifiées.
2. **Sur-mesure caché** : demande client hors standard absorbée dans un prix fixe.
3. **Qualité des données** : export instable, identifiant absent, dossiers mal nommés.
4. **Adoption** : assistante surchargée ou terrain qui n'utilise pas le canal.
5. **Dépendance fournisseur** : WhatsApp, messagerie, transcription ou ERP modifiés.
6. **Support non rentable** : MCO trop généreux ou périmètre flou.
7. **Risque juridique et sécurité** : accès, sous-traitants, sauvegardes ou suppression mal documentés.
8. **Réutilisation de code non autorisée** : dépôt sans licence ou dépendance non maîtrisée.
9. **Fonction déjà native dans l'ERP** : valeur VotrIA insuffisante.
10. **Promesse commerciale excessive** : réputation locale dégradée.

## BLOC 14 — Architecture technique et stratégie de réutilisation

### 14.1 Principe

> Construire le moins possible. Réutiliser les composants sérieux. Ajouter uniquement la couche métier VotrIA.

### 14.2 Socle cible

- n8n pour l'orchestration ;
- Python uniquement pour le moteur métier réutilisable ;
- Pivot VotrIA pour normaliser les données ;
- environnement dédié appartenant au client ;
- configuration client séparée du code ;
- secrets hors Git ;
- monitoring sans remontée de contenu métier lorsque possible.

### 14.3 Réutilisation de dépôts et workflows existants

Avant tout développement :

1. chercher un workflow, dépôt ou produit existant ;
2. vérifier la licence ;
3. vérifier l'activité du projet ;
4. vérifier les dépendances payantes ou propriétaires ;
5. tester l'installation ;
6. supprimer les fonctions inutiles ;
7. ajouter le masque métier VotrIA ;
8. chronométrer l'installation complète.

Licences privilégiées : MIT, Apache 2.0, BSD.

Un dépôt public sans licence n'est pas réutilisé commercialement sans autorisation explicite.

### 14.4 Dépôt privé VotrIA

Le dépôt VotrIA contient uniquement :

- configurations standard ;
- workflows adaptés ;
- modèles métier ;
- scripts d'installation et de sauvegarde ;
- tests ;
- documentation ;
- versionnement des composants VotrIA.

Il ne contient jamais :

- données de production ;
- clés API ;
- jetons ;
- vocaux ;
- photos ;
- emails ;
- sauvegardes client.

### 14.5 Architecture d'hébergement

Modèle standard :

> **Client propriétaire, VotrIA administrateur selon le MCO choisi.**

- environnement cloud ou service dédié au nom du client ;
- serveur local uniquement si un prestataire informatique client l'administre ;
- aucune instance mutualisée VotrIA au lancement ;
- accès VotrIA nominatif et révocable ;
- sauvegarde et sortie prévues dès l'installation.

### 14.6 Profils ERP

Aucun ERP n'est annoncé comme « connecté API » sans validation réelle.

Ordre de travail :

1. CSV/Excel standard ;
2. profils logiciels déjà testés ;
3. API uniquement lorsqu'elle est documentée, accessible et économiquement justifiée.

VotrIA intervient sur :

- rupture entre outils ;
- donnée hors ERP ;
- processus non suivi ;
- règle métier absente ;
- restitution plus simple pour l'équipe.
